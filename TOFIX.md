## 1. Сломано / не работает end-to-end

### 1.1. Кнопка «показать API-ключ» прячет поле вместо показа
- **Файл:** `src/LinguaLens.App/Windows/SettingsWindow.xaml.cs:37-49`
- **Что не так:** обработчик переключает `ApiKeyBox.Visibility` (Visible ↔ Collapsed) вместо того, чтобы показать plaintext.
- **Почему важно:** прямо противоположное от ожидаемого поведения. Пользователь жмёт «показать» — поле исчезает. Для UI настроек, к которому будут возвращаться редко, это «удивляющий баг», который раздражает каждый раз.
- **Минимальный фикс:** заменить `PasswordBox` + кнопка на пару `PasswordBox`/`TextBox` с переключением Visibility между ними по клику; или переключать `PasswordChar`.

### 1.2. Escape не закрывает оверлей
- **Файл:** `src/LinguaLens.App/Overlay/OverlayWindow.xaml` (атрибуты окна) и `OverlayWindow.xaml.cs:170` (`OnKeyDown` override).
- **Что не так:** окно создаётся с `ShowActivated=False`/`Focusable=False`, и `.Show()` фактически никогда не вызывается — переключается только `Visibility`. KeyDown в неактивированное и нефокусируемое окно не приходит.
- **Почему важно:** в ТЗ §2.1 явно сказано «карточка исчезает … по нажатию Escape». Это базовое UX-обязательство.
- **Варианты фикса:** (а) сделать окно `Focusable=True`, вызывать `Show()` и `Activate()`, либо (б) повесить глобальный `InputManager.Current.PreProcessInput` хендлер на VK_ESCAPE, пока оверлей видим.

### 1.3. Чекбокс «Изучено» в словаре не сохраняется
- **Файл:** `src/LinguaLens.App/Windows/VocabWindow.xaml:28` (DataGrid column) + `Core/Models/Models.cs` (`VocabEntry`).
- **Что не так:** `VocabEntry` — `record` с init-only свойствами, two-way binding на `IsLearned` фактически не работает (либо тихо мутирует копию, либо проброс не происходит). `IVocabRepository.MarkLearnedAsync` никогда не вызывается из UI.
- **Почему важно:** одна из заявленных функций словаря (ТЗ §2.3). Пользователь думает, что отметил слово, перезапускает приложение — отметка пропала.
- **Минимальный фикс:** обернуть строку в `VocabEntryViewModel` с обычными set-аксессорами, на `PropertyChanged(IsLearned)` дёргать репозиторий.

### 1.4. «Перевести предложение →» из карточки слова обычно возвращает пусто
- **Файл:** `src/LinguaLens.App/Overlay/DebounceController.cs:142` `OnTranslateSentenceRequested`.
- **Что не так:** обработчик зовёт `ProcessSelectionAsync()` без заранее извлечённого текста. К моменту клика по кнопке фокус уже в оверлее, выделение в исходном приложении в большинстве случаев потеряно (или вообще не делалось).
- **Почему важно:** «перевести предложение» — один из двух главных пользовательских сценариев. Если кнопка нажимается и почти всегда возвращает «ничего» — функция мертва на практике.
- **Фикс:** сохранять `sentence` из `WordExtractionResult` в `WordCardViewModel`, при клике на «Перевести предложение» переводить именно этот `sentence`, а не пытаться снова читать выделение.

### 1.5. Сохранение в словарь из карточки теряет контекст
- **Файл:** `src/LinguaLens.App/ViewModels/WordCardViewModel.cs:46`
- **Что не так:** `SaveToVocabCommand` зовёт `SaveAsync(result, contextSentence: "", sourceApp: "manual")`. Реальное `sentence` и реальное имя процесса, извлечённые во время перевода, отбрасываются.
- **Почему важно:** при экспорте в Anki/CSV у таких записей не будет примера из реального контекста и пометки источника — основная ценность словаря падает. Автосохранение через оркестратор делает правильно, ручное — портит данные.
- **Фикс:** прокинуть `WordExtractionResult` или хотя бы `sentence`+`sourceApp` в VM и использовать их в команде.

### 1.6. Hint-кнопка «Перевести» в правом нижнем углу при выделении не реализована
- **Файл:** в коде нет; ТЗ §2.2.
- **Что не так:** ТЗ обещает: пользователь выделяет текст → в правом нижнем углу появляется кнопка-подсказка → клик → перевод. В коде есть `GlobalMouseHook.SelectionChanged`, но он не запущен и никто не подписан. Единственный путь к sentence-режиму сейчас — хоткей.
- **Почему важно:** это заявленная фича. Решение «оставить только хоткей» — допустимый трейд-офф, но тогда стоит зафиксировать решение в ТЗ, а не считать пунктом ToDo.
- **Развилка:** либо реализовать hint-кнопку, либо вычеркнуть из ТЗ §2.2 как out of scope.

### 1.7. Cache hit не укладывается в <50 мс
- **Файл:** `src/LinguaLens.Core/Services/TranslationOrchestrator.cs` (`ProcessHoverAsync` — текущий код всегда зовёт extractor до cache lookup).
- **Что не так:** UIA `ExtractWordAtPointAsync` выполняется *перед* `cache.GetAsync`. UIA — самая медленная операция в пайплайне (десятки–сотни мс). Кэш-хит платит за UIA.
- **Почему важно:** ТЗ §3 — latency cache hit < 50 мс. Сейчас фактически 100–500 мс.
- **Замечание:** не очевидно, как фиксить без потери контекста — кэш-ключ зависит от `sentence`, который мы и извлекаем UIA. Возможен компромисс: ключ только по слову (без хэша контекста) + второй уровень с контекстом. Решение требует обсуждения.

### 1.8. `Toggle` в трее не освобождает хоткей
- **Файл:** `src/LinguaLens.App/App.xaml.cs:63-74` и `TrayIconManager.cs`.
- **Что не так:** при «выключено» приложение просто игнорирует `TranslateRequested`. Сам хоткей остаётся зарегистрирован в Windows, и другие приложения не могут его перехватить.
- **Почему важно:** пользователь, выключивший LinguaLens, ожидает, что `Ctrl+~` снова свободен — особенно потому, что эта комбинация используется во многих IDE (терминал VS, Cursor и т.д.).
- **Фикс:** в `TrayIconManager` добавить `UnregisterHotKey`/`RegisterHotKey` по сигналу `Toggle`, либо отдельный публичный `SetHotkeysEnabled(bool)`.

## 3. Мёртвый код / чистка / переименования

### 3.1. `GlobalMouseHook` целиком мёртв
- **Файл:** `src/LinguaLens.Infrastructure/Hooks/GlobalMouseHook.cs` (148 строк) + регистрация в `App.xaml.cs:170`.
- **Что не так:** регистрируется в DI, никем не резолвится, `Start()` не вызывается. Весь low-level mouse hook, P/Invoke, `Channel`-pump, `SelectionChanged` event — впустую.
- **Почему важно:** вводит в заблуждение читателя кода и оставляет «ружьё на стене» — если кто-то случайно подпишется на `MouseMoved`, hover вернётся неконтролируемо. Лучше удалить полностью; вернуть из git, если когда-нибудь понадобится.

### 3.2. `DebounceController` — название врёт
- **Файл:** `src/LinguaLens.App/Overlay/DebounceController.cs`.
- **Что не так:** после удаления hover там нет ни одного `Timer` для debounce. Это «обработчик ручного триггера + полуночный сброс предупреждения по токенам + проксирование событий оверлея».
- **Почему важно:** новый разработчик (или ты через 3 месяца) увидит имя `DebounceController` и предположит, что класс отвечает за подавление частых событий — и потратит время на разочарование.
- **Фикс:** переименовать (например, `ManualTranslationController` или `TranslationCommandRouter`).

### 3.3. `DebounceMs` слайдер в настройках — нерабочий
- **Файл:** `SettingsWindow.xaml:33`, читается в `AppSettings`, но в коде никто не читает `settings.DebounceMs`.
- **Что не так:** UI сохраняет значение, оно никак не влияет на поведение.
- **Почему важно:** наёбывает пользователя. Либо реально использовать (например, в hover-сценарии, если он вернётся), либо убрать из UI.

### 3.4. `ClipboardTextExtractor` нерабочая часть цепочки
- **Файл:** `src/LinguaLens.Infrastructure/TextExtraction/ClipboardTextExtractor.cs`, потребитель — `CompositeTextExtractor`.

- **Почему важно:** ТЗ §4 явно описывает clipboard как фоллбэк для sentence-режима. Либо вернуть его в путь (через `ITextExtractor` композит), либо удалить класс. Сейчас он — половинчатая абстракция, которая делает вид, что работает.

### 3.5. `CsvVocabExporter` зарегистрирован, но не используется

  - либо удалить `CsvVocabExporter` и оставить CSV-экспорт в `AnkiExporter` (странно, но работает),
  - либо разделить через два интерфейса/именованную регистрацию и реально использовать оба.

## 4. Несогласованности с ТЗ / документацией

### 4.1. Триггер перевода: hover vs хоткей
- **Файл:** ТЗ §1 и §2.1 («при наведении курсора … 400 мс debounce»).
- **Что не так:** реализация теперь — только хоткей `Ctrl+~`. Hover отключён, `DebounceMs` неактуален. ТЗ описывает hover как основной режим.
- **Почему важно:** ТЗ — источник правды; пока он расходится с кодом, любой следующий аудит будет считать hover «не реализованным». Зафиксировать решение: либо обновить ТЗ §1, §2.1, §2.4 (debounce → горячая клавиша), либо вернуть hover.

- **Файл:** `App.xaml.cs:121`.
- **Что не так:** `SetMinimumLevel(LogLevel.Warning)`. `LogInformation`/`LogDebug` отбрасываются.
- **Почему важно:** возможно, осознанный выбор (продакшен-уровень). Но в фазе активной разработки маскирует полезные сигналы. Стоит вынести в `AppSettings` или дёргать из переменной окружения.
